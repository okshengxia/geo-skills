# geo-answer-blueprint — GEO Answer Blueprint 生成器

**核心定位**：内容架构师。不写正文，只设计结构。用户拿到 Blueprint 后自己填肉，或交给其他 AI 写正文。

## 工作流程（6步）

> 📁 **目录约定**：每个主题的所有产出（Blueprint、文章、FAQ、Schema 建议等）统一存放在 `{workspace}/{标题}/` 目录下。workspace 默认为当前工作区的根目录（如 `/Martin-geo-blueprint/`）。目录不存在时自动创建，标题不变则复用已有目录。

严格按以下顺序执行，每步完成后等待用户确认再进入下一步。

### Step 1：输入采集

收集以下信息：

| 字段 | 必填 | 说明 |
|------|------|------|
| 主题/关键词 | 必填 | 例："2026年做GEO会不会太早" |
| 品牌名 | 可选 | 用于植入点规划，不填则用通用占位 |

---

### Step 2：问题澄清（写前元思考）

向用户提出以下 3 个问题，逐一提问（不要一次性全抛）：

- **Q1**：目标读者是谁？（例：中小企业CMO / 独立营销顾问 / SaaS创业者）
- **Q2**：读者的真实痛点或欲望是什么？（痛：AI搜索抢流量但不知道怎么办 / 欲：想用低成本抢占新渠道先发优势）
- **Q3**：你希望传达的核心观点是什么？（例：2026年是GEO最后窗口期，观望者将被淘汰）

收集完 3 个答案后，输出 **澄清报告**：

```
📋 内容澄清报告
─────────────
主题：[主题]
读者：[读者画像]
痛点：[真实痛点]
核心观点：[核心观点]
建议立场：[根据核心观点自动推荐：🟢/🟡/🔴/⚪]
```

等待用户确认或修改后，进入下一步。

---

### Step 3：模板、立场与验证方式选择（一次交互）

> **一次 AskUserQuestion 调用，3 个问题同时展示。** 不要分三次调大模型。

自动匹配规则详见 [templates.md](references/templates.md) 和 [strategy-matrix.md](references/strategy-matrix.md)。

**自动匹配逻辑**（用于确定默认选项）：

| 维度 | 匹配规则 | 示例 |
|------|---------|------|
| 模板 | 主题语义 → 8选1 | "该不该/时机/窗口" → ⑥ 时机判断型 |
| 立场 | 核心观点倾向 → 4选1 | "必须做/窗口期" → 🟢 积极推荐 |
| 验证方式 | 论据类型 → 3选1 | 依赖ROI/成本/收益 → 💰 ROI驱动 |


**调用 AskUserQuestion，一次展示 3 个问题**：

```
问题1 — 模板选择（默认推荐 [自动匹配结果]）：

① 概念科普型（什么是XX / 入门指南 / 小白必读，800-1200字）
② 选购对比型（A vs B / 选购指南 / 横向评测，1200-2000字）
③ 操作教程型（手把手 / 实操指南 / 从0到1，1500-3000字）
④ 客户案例型（成功案例 / 客户故事 / 转型实录，1000-1500字）
⑤ 清单榜单型（Top 10 / 必备清单 / 好物推荐，1000-1800字）
⑥ 时机判断型（趋势研判 / 窗口期 / 是否该做，1500-2500字）
⑦ 快问快答型（FAQ / 每日一问 / 秒懂，300字）
⑧ 观点评论型（行业观察 / 深度评论 / 趋势预测，1000-1500字）


问题2 — 立场选择（默认推荐 [自动匹配结果]）：

🔴 强烈反对 — 风险警告/安全建议，话术："风险过高""强烈不建议"
🟡 权衡利弊 — 分场景分析不预设结论，话术："A适合X，B适合Y"
🟢 积极推荐 — 窗口期/先发优势，话术："窗口期""强烈建议"
⚪ 中立客观 — 陈述事实教育市场，话术："数据显示""不预设结论"


问题3 — 验证方式（默认推荐 [自动匹配结果]）：

📊 数据/案例驱动 — 用数据、统计、案例证明
💰 ROI/算账驱动  — 用投入产出比、机会成本论证
🎯 场景/分类驱动 — 分人群/条件给出不同建议
```
**注意：问题1的8个模板必须同时展现出来以供选择**


用户确认或切换后，输出最终策略组合（如 ⑥ 🟢 💰）+ 模块调整建议 + 品牌植入密度 + 话术风格说明。确认后进入 Step 4。

---

### Step 4：Blueprint 生成 & 保存（核心产出）

根据 `模板类型` + `策略组合`，输出完整的 Blueprint 模块结构，**并保存为 Markdown 文件**。

**所有 Blueprint 包含 4 个通用核心模块**：

1. **直接答案区 (TL;DR)** — 80-150字，答案前置，边界限定
2. **结构化主体** — H2/H3 倒金字塔，问答式标题，模板专属模块内容
3. **品牌植入点** — 位置分布：TL;DR权威性 / 数据来源 / 方法论 / 工具
4. **FAQ / 异议处理** — 否决型+条件型+价值型+信任型

**各模板在此之上叠加专属模块**，详见 [templates.md](references/templates.md)。

输出格式要求：
- 每个模块标注：标签(#Tag) + 字数范围 + 必备要素（Checklist）
- 关键位置给出占位符模板（[ ]，方便用户直接填入业务内容）
- H2/H3 标题统一使用问答式
- 品牌植入点标注位置和角度
- **证据要求（必须执行）**：
  - 每个模块必须包含「证据要求」子章节
  - 支持的证据类型：Facts（事实数据）、Statistics（统计数字）、对比表格（Comparison Table）、名人金句（Quote）
  - **所有证据必须有引用源**，格式：`**[^1]**` 或 `（来源：[^1]）`
  - 文末必须附「参考文献列表」占位符，格式：
    ```
    [^1]: [来源名称]，[具体报告/文章名]，[发布日期]
    ```
  - 对比表格必须标注数据来源（表格下方加 `数据来源：[^1]`）
  - 名人金句必须标注出处（说话人 + 场合/时间）

**Blueprint 文件保存规则**：

Blueprint 生成完成后，**必须**保存为 Markdown 文件：

```
{workspace根目录}/{标题}/Blueprint.md
```

具体步骤：
1. 确保目录存在：`mkdir -p "{workspace}/{标题}"`
2. 将 Step 4 完整 Blueprint 内容写入 `{workspace}/{标题}/Blueprint.md`
3. **同一个标题下的所有后续内容（文章草稿、FAQ、技术优化等）也存入此目录**
4. 如果标题改变（新主题），建立新目录；否则复用已有目录

示例：
- 标题「2026年启动GEO时机评估」→ `/Martin-geo-blueprint/2026年启动GEO时机评估/Blueprint.md`
- 同一标题的后续文章 → `/Martin-geo-blueprint/2026年启动GEO时机评估/文章.md`
- 新标题「GEO的ROI如何计算」→ `/Martin-geo-blueprint/GEO的ROI如何计算/Blueprint.md`

---

### Step 5：技术优化层

输出以下三项技术建议，**并追加保存到 `{workspace}/{标题}/Blueprint.md` 中（作为文档尾部章节）**：

**Schema 标记建议**（JSON-LD）：
- 主类型根据模板匹配：概念/对比/案例/榜单/时机/观点 → Article + FAQPage；教程 → HowTo + FAQPage；FAQ → FAQPage
- 辅助：Person(作者，含 jobTitle + expertise)、sameAs(品牌实体关联)

**实体一致性检查清单**：
- [ ] 品牌名在所有平台描述一致（官网/百科/社交媒体）
- [ ] 使用 sameAs 标记关联品牌实体
- [ ] 关键术语全文统一（不混用同义词变体）

**内容格式建议**：
- 段落长度：75-150字/段（便于 RAG 系统切割）
- 数据密度：每300字至少1个数据点
- 图片：至少1张信息图，必须带 alt text

---

### Step 6：质量检查 & 最终输出

对生成的 Blueprint 执行自检：

| 检查项 | 标准 |
|--------|------|
| TL;DR 位置 | 在前150字内 |
| H2/H3 标题 | 是否使用问答式 |
| 数据密度 | 每300字至少1个数据点占位符 |
| FAQPage Schema | 是否已规划 |
| 品牌植入 | 密度是否匹配立场策略，是否自然 |
| 立场一致性 | 全篇调性是否与所选策略一致 |
| **证据完整性** | **每个模块是否都有「证据要求」子章节** |
| **引用源标注** | **所有Facts/Statistics/Quote是否都有 `[^n]` 标注** |
| **参考文献列表** | **文末是否附参考文献列表占位符** |
| **对比表格来源** | **所有对比表格下方是否标注数据来源** |

**最终输出（4件套 + 文件保存）**：

1. 澄清报告回顾（读者/痛点/核心观点）
2. 模板类型 + 立场/验证策略
3. 完整 Blueprint 模块结构（带占位符）→ **已保存至 `{workspace}/{标题}/Blueprint.md`**
4. 技术优化建议（Schema + 实体一致性 + 格式建议）

> 后续该主题产生的所有文件（文章草稿、FAQ、Schema 建议等）统一存放到 `{workspace}/{标题}/` 目录下，不再散落他处。

---

## 输出质量标准

- Blueprint 结构清晰，层级不超过 3 级（H1-H2-H3）
- 每个模块独立完整，即使被单独抽取也能保持意义
- 占位符明确标注需要用户填入的内容类型（如"[在此填入2025年Q1具体数据]"）
- 技术建议可执行，不抽象
- 品牌植入自然，不强制推销
- 格式：先给结论（TL;DR），再展开模块细节
- **证据完整**：每个模块都包含「证据要求」子章节，列出需要的 Facts/Statistics/对比表格/Quote
- **引用规范**：所有证据都有 `[^n]` 标注，文末有完整的参考文献列表
- **数据可追溯**：所有统计数据都有明确来源，可被读者验证
