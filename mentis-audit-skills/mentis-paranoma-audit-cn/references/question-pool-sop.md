# 问题池与机会地图 SOP（阶段0 模块3+4：QUESTION_POOL / OPPORTUNITY_MAP）

> 适用：mentis-paranoma-audit-cn 阶段0。字段契约见 `prompts.md` 阶段0 模块3+4。

## 一、九类意图定义

| 意图 | 定义 | 示例句式（猎头业） |
|------|------|--------------------|
| 推荐 | 求推荐清单 | 「高管寻访公司推荐」 |
| 比较 | 多品牌对比 | 「亿康先达和光辉国际哪个好」 |
| 替代 | 找替代方案 | 「除了亿康先达还有什么猎头」 |
| 教程 | 方法论/流程 | 「怎么选猎头公司/寻访流程」 |
| 价格 | 费用/报价 | 「亿康先达收费贵吗」 |
| 风险 | 风险/负面 | 「亿康先达靠谱吗/投诉」 |
| 真实性 | 资质/真伪 | 「亿康先达是真的吗/官方」 |
| 购买决策 | 决策前最后确认 | 「该不该找亿康先达」 |
| 场景解决 | 具体场景 | 「CEO 继任找哪家」 |

- `sampleQuestions`：2-3 个**真实风格问句**（含口语化变体），不写书面语。
- `brandPresence`：present / partial / absent——**⚠️预判值**，依据平台矩阵的信源结构推理，非实测。

## 二、信源缺口写法

- 缺口必须落到「**哪个意图下、缺哪类信源**」：
  - ✅「推荐意图：小红书/知乎无品牌结构化内容，AI 无可引用原子单位」
  - ❌「内容不足」
- `gapSeverity`：high（核心商业意图零覆盖）/ medium（有覆盖但弱）/ low（边缘意图缺口）。
- `priority`：与 severity 对齐，P0 缺口必须能指回 platformMatrix 的具体空格。

## 三、机会地图字段

| 字段 | 规范 |
|------|------|
| id | OPP-NN 顺序编号 |
| priority | P0（1-2 周必做）/ P1（1-3 月）/ P2（3-6 月） |
| title | 动词开头，一句话行动 |
| rationale | 引用具体数据（哪平台哪格为空/哪个同名实体 high） |
| relatedStageCodes | 关联 stageCode（ENTITY_MAP/PLATFORM_MATRIX/QUESTION_POOL…） |
| actions | 2-4 个可执行动作 |
| acceptanceCriteria | **可度量验收标准**（见下） |
| expectedImpact | 对 AI 可引用性/口碑的预期改变 |

## 四、验收标准句式（可度量）

- ✅「百度百科词条消歧段包含『猎头』字样」
- ✅「官网/官方公众号出现收费模式 FAQ，覆盖 Top3 流传口径」
- ❌「提升品牌形象」「加强内容建设」

句式模板：「**{平台/载体} 出现 {可验证内容}，且 {可验证条件}**」。

## 五、优先级判定规则

- **P0**：同名实体污染（high）/ 核心商业意图零覆盖 / 收费或合规口径裸奔（第三方流传无官方佐证）。
- **P1**：主平台覆盖不全 / 情感偏负且无对冲内容 / 别名矩阵不统一（中繁英混用）。
- **P2**：长尾意图缺口 / 边缘平台缺位。

## 六、openQuestions（待确认项）

- confidence<0.7 的断言、需业务侧确认的事实（合同条款、组织架构、未公开定价），一律进 openQuestions，每条带 `question + whyItMatters`。
- 报告展示为「待确认项」章节，**不当作结论呈现**。

## 七、输出

→ `stage0.json` 的 `questionPool` 与 `opportunityMap` 模块。
