# GEO诊断报告 - 搜索增强策略与执行规范

---

## 证据优先（v2.0 硬纪律）

| 情形 | 处理 |
|------|------|
| WebSearch 可用 | 采集真实结果，每条断言记录 URL + 日期 |
| WebSearch 部分不可用 | 已取到的照常入报告；取不到的标「未获取」，**不得用 AI 推理补位** |
| WebSearch 完全不可用 | **中止流水线并告知用户**：本 skill 禁止输出无证据的推断内容 |

**没有"降级为 AI 推理"这一档。** 报告里出现的每个数字、每条断言都必须能点回原始页面。

## 并行搜索策略（v4.0优化）

> 核心优化：将串行搜索改为分组并行，减少网络等待时间。

### 阶段0 搜索组（站外全景审计，4组并行）

| 组别 | 搜索词 | 并行方式 |
|------|--------|----------|
| **组A：实体消歧（并行）** | "{brand}" 百科 品牌介绍、"{brand}" 公司 主体 成立、"{brand}" 英文名 OR 曾用名 | 3次WebSearch同时发起 |
| **组B：同名实体（并行）** | "{brand}" 是什么、"{brand}" 招聘 评价 OR 新闻 | 2次WebSearch同时发起 |
| **组C：平台矩阵（并行）** | "{brand}" site:zhihu.com OR site:xiaohongshu.com、"{brand}" 收费 价格 OR 多少钱、"{brand}" 靠谱 投诉 合规 | 3次WebSearch同时发起 |
| **组D：信源缺口（并行）** | "{productType}" 推荐 排行、"{brand}" 对比 哪个好 | 2次WebSearch同时发起 |

> 阶段0 约 11 次搜索；组A结果写 `search-cache/{brand}-entity.json`（TTL 30min），阶段1组A命中缓存则跳过重复搜索。

### 阶段1 搜索组

| 组别 | 搜索词 | 并行方式 |
|------|--------|----------|
| **组A（并行）** | 品牌官网+品牌介绍、竞品信息、评测报道 | 3次WebSearch同时发起 |
| **组B（并行）** | 自媒体site搜索、权威媒体site搜索 | 2次WebSearch同时发起 |

组A和组B可串行（组A先执行，结果供组B参考调整），也可并行（若无需动态调整查询词）。

### 阶段2 搜索组

| 组别 | 搜索词 | 并行方式 |
|------|--------|----------|
| **组A（并行）** | "{brandName} {productType} 推荐"、"{brandName} {productType} AI搜索" | 2次WebSearch同时发起 |

### 阶段3 搜索组

| 组别 | 搜索词 | 并行方式 |
|------|--------|----------|
| **组A（并行）** | 负面投诉、口碑评价、风险争议 | 3次WebSearch同时发起 |

### 跨阶段并行

阶段2和阶段3**互不依赖**，可同时开始执行：
- 阶段2的搜索 + 阶段3的搜索 → 同时发起
- 阶段2的推理 + 阶段3的推理 → 同时执行

## 搜索缓存策略（v4.0优化）

> 对同一品牌+产品的重复诊断，缓存搜索结果避免重复请求。

### 缓存规则

| 缓存键 | 格式 | 过期时间 | 适用场景 |
|--------|------|----------|----------|
| 实体缓存 | `search-cache/{brand}-entity.json` | 30分钟 | 阶段0实体身份+平台矩阵（供阶段1组A复用） |
| 基建缓存 | `search-cache/{brand}-{product}-infra.json` | 30分钟 | 官网、媒体报道（变化慢） |
| 竞品缓存 | `search-cache/{brand}-{product}-competitor.json` | 1小时 | 竞品信息（变化很慢） |
| 舆情缓存 | `search-cache/{brand}-{product}-sentiment.json` | 15分钟 | 舆情数据（变化快） |

### 缓存命中判断

1. 检查 `diag-output/search-cache/` 下是否存在对应缓存文件
2. 读取缓存文件的 `cachedAt` 时间戳
3. 若未过期，直接使用缓存结果，跳过搜索
4. 若已过期或不存在，执行搜索并写入缓存

### 缓存文件格式

```json
{
  "cachedAt": "2026-06-10T10:30:00+08:00",
  "brand": "华为",
  "product": "汽车",
  "type": "infra",
  "results": [
    {"query": "华为汽车 品牌介绍", "items": [...]}
  ]
}
```

## 各阶段搜索增强点

| 阶段 | 搜索目标 | 搜索方式 | 降级策略 |
|------|----------|----------|----------|
| ENTITY_MAP（阶段0） | 官方主名/主体/成立年份/别名 | WebSearch: 组A+组B | 取不到的标「未获取」，confidence<0.7 转 openQuestions，**禁推断补位** |
| PLATFORM_MATRIX（阶段0） | 13平台×5类覆盖证据 | WebSearch: 组C | 缺失平台标「未获取」，禁编 URL；不输出 AI 预判列 |
| QUESTION_POOL（阶段0） | 品类推荐/对比信源 | WebSearch: 组D | 无信源的意图如实记为缺口 |
| INFRA_EVAL step2 | 自媒体报道URL/标题 | WebSearch: 品牌词+平台site搜索 | 无结果则记 0 条，**不得虚构报道** |
| INFRA_EVAL step3 | 权威媒体报道URL/标题 | WebSearch: 品牌词+媒体site搜索 | 无结果则记 0 条，**不得虚构报道** |
| COMPETITOR | 竞品公开信息 | WebSearch: 品类排名/推荐 | 取不到则只列已证实的竞品 |
| SENTIMENT step1 | 舆情查询词 | 无需搜索（由实体/品类推导） | — |
| AI_SEARCH（阶段2） | AI 常引用信源上的可引用内容 | WebSearch: 品牌+信源site搜索 | 每条证据带 URL；无证据则该维度记 null |
| OVERVIEW/AIVO_SCORE/SUGGESTION（阶段4） | 汇总前序证据，不新增搜索 | — | 无证据的维度记 null |

## 搜索增强优先级

0. **阶段0（站外全景审计）优先使用搜索增强**：实体消歧与平台矩阵的每条断言都带URL要求，是全流水线搜索密度最高的阶段
1. **有URL要求**的阶段优先使用搜索增强（INFRA_EVAL step2/step3）
2. **有事实性要求**的阶段次优先（COMPETITOR 市场份额、竞品信息）
3. **汇总类**阶段无需新搜索（OVERVIEW / AIVO_SCORE / SUGGESTION 仅汇总前序证据）

### 搜索策略

始终使用搜索增强：优先 WebSearch 获取真实证据，**搜索失败不降级为推理**——取不到就如实标注未获取。

---

## 速率控制

- 同一搜索引擎：请求间隔 1-2 秒
- **并行搜索：同组搜索同时发起，不设间隔（v4.0优化）**
- 批量搜索：组间间隔 1 秒（v4.0优化，原2秒）

## 重试与容错

| 异常 | 处理 |
|------|------|
| 搜索超时/无结果 | 重试1次，换引擎 |
| 搜索结果不相关 | 扩大/调整查询词，重试1次 |
| WebSearch 完全不可用 | **中止流水线并告知用户**（本 skill 不接受无证据输出） |
| 返回403/429 | 如有cookie机制则刷新后重试1次 |

---

## 结果验证

- URL格式校验：必须以 http(s):// 开头
- 内容相关性：搜索结果标题/摘要需包含品牌词或产品词
- 去重：同一URL只保留一条
- 时效性：优先展示近1年内内容
