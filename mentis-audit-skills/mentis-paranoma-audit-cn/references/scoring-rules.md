# GEO诊断报告 - 评分规则与质量标准

---

## 四维评分模型（证据化）

四维等权重评分，总分 = **有分维度** score × weight 的加权平均。

> **硬纪律：每一维必须挂证据链 `evidence: [{url, date, supports}]`。某维没有可核验证据时，`score` 记 `null`，不参与加权，并在 `comment` 写明「未获可核验证据」。总分的 `commentary` 必须注明实际参评维度数。**

| 维度 code               | 中文名        | 权重   | 计分依据（全部为可核验事实）                                                         |
| --------------------- | ---------- | ---- | ---------------------------------------------------------------------- |
| AI_SEARCH_VISIBILITY  | AI 可引用内容覆盖 | 0.25 | AI 常引用信源（百科/权威媒体/问答/行业报告/官网）上，品牌可被引用内容的覆盖广度与深度。**禁用提及率**——本报告未实测 AI 输出 |
| INFRA_COMPLETENESS    | 基建完善度      | 0.25 | 官网是否可访问且内容完整、自媒体账号是否存在且活跃、权威媒体报道条数（每条带 URL）                            |
| COMPETITIVE_ADVANTAGE | 竞品对比优势     | 0.25 | 同信源上的证据条目数/权威度与主要竞品的对比                                                 |
| SENTIMENT_HEALTH      | 舆情健康度      | 0.25 | 已采集舆情条目中的负面占比与风险等级（样本量与来源须列明）                                          |

评级：≥90 优秀 / ≥75 良好 / ≥60 一般 / <60 较差

### 评分锚定规则（证据计数制）

| 维度         | 锚定条件（基于证据条目）               | 分数区间             | 无证据    |
| ---------- | -------------------------- | ---------------- | ------ |
| AI 可引用内容覆盖 | 五类 AI 常引用信源全覆盖且条目充足（≥12 条） | 80-95            | `null` |
|            | 覆盖 3-4 类（6-11 条）           | 60-79            |        |
|            | 覆盖 1-2 类（1-5 条）            | 35-59            |        |
|            | 0 条                        | 10-34            |        |
| 基建完善度      | 官网可访问 + 自媒体活跃 + 权威媒体 ≥10 条 | 80-95            | `null` |
|            | 三项齐备但条目 5-9 条              | 60-79            |        |
|            | 缺其中一项                      | 40-59            |        |
|            | 无官网或官网不可访问                 | 15-39            |        |
| 竞品对比       | 证据条目数/权威度 > 竞品均值           | 75-95            | `null` |
|            | 与竞品均值相当                    | 55-74            |        |
|            | 明显弱于竞品均值                   | 25-54            |        |
| 舆情健康       | 已采集条目负面率 <10%（样本 ≥10）      | 85-100           | `null` |
|            | <20%                       | 70-84            |        |
|            | <35%                       | 50-69            |        |
|            | ≥35%                       | 20-49            |        |
|            | 样本 <10 条 → 不评分             | 记 `null` 并说明样本不足 |        |

微调幅度：±5 分。**任何微调都要能指回具体证据。**

## 输出裁剪规则

> 裁剪规则仅用于 **HTML报告展示**，不影响 prompts.md 中的生成数量要求（如自媒体至少10条）。  
> AI生成时按prompts.md数量输出完整数据，HTML渲染时按裁剪规则截取展示。

| 字段               | 上限          | 理由                    |
| ---------------- | ----------- | --------------------- |
| questionDetails  | 5条          | 概览足够                  |
| competitors      | 5条          | 前5竞品（v4.0优化，原数据已限制5个） |
| INFRA_EVAL.items | 3条/类        | 概览足够                  |
| SENTIMENT.issues | 5条          | 关键问题                  |
| suggestions      | priority前5条 | 聚焦优先                  |
| quickWins        | 3条          | 快速赢利                  |

## 解读质量检查

输出前逐项检查：

- [ ] 12 章均有数据（缺 stage 的章节自动隐藏，不占编号）
- [ ] 四维评分均有 score + comment + evidence，totalScore = **有分维度** score×weight 的加权平均；无证据的维度记 `null`
- [ ] 同一份报告内的「证据条数」口径可对齐（10 章须写明与 06 章的差额来源）
- [ ] 评级颜色匹配分数范围（≥90优秀 / ≥75良好 / ≥60一般 / <60较差）
- [ ] 每个风险至少配一条建议
- [ ] 建议具体到"做什么→预期效果"
- [ ] 进度条 width=score%
- [ ] 章节编号 01-12（四幕）对齐前端
- [ ] 对外文案无 `AIVO`、无「AI 可见性 / AI 搜索可见度」；hero 分数与评级未使用暖色（青绿底上对比度不足）

## 反模式

| ❌ 反模式         | ✅ 正确做法                                                  |
| ------------- | ------------------------------------------------------- |
| "品牌表现很差"      | "舆情健康度58分，低于行业基准65分"                                    |
| "建议加强品牌建设"    | "[P0] 增加通义千问平台内容覆盖 → 预计提升可见性8分"                         |
| 列出所有竞品详情      | 展示前5竞品，说"详情"看更多                                         |
| 编造不存在的数据      | 缺证据的条目写进待确认项或标注「未获取」，绝不为凑报告编数                           |
| 用 AI 推理填补搜索空白 | 取不到就如实标 0 条/未获取                                         |
| 同时出现两套评分      | 全报告只有一个分数（`AIVO_SCORE.totalScore`），12 章的预测值必须显式标"目标/预测" |
| 只说问题不给方案      | 每个风险配一条建议行动                                             |

## 异常处理

| 异常            | 处理                                    |
| ------------- | ------------------------------------- |
| JSON解析失败      | 重试1次，仍失败标注⚠️跳过                        |
| 字段缺失          | 记 `null` 并在报告写明「未获取」，**禁用编造值填充**      |
| 序数据空          | 标注"前序数据缺失"，基于可用数据执行                   |
| 某维无证据         | `score` 记 `null`，不参与加权，`comment` 写明原因 |
| WebSearch 不可用 | **中止并告知用户**（v2.0 不接受无证据输出）            |
| 搜索超时/无结果      | 重试1次，换搜索引擎                            |

## 模型适配指导

| 模型系列        | JSON可靠性 | 适配要点               |
| ----------- | ------- | ------------------ |
| GPT-4o / o1 | 高       | 原生支持，无需特殊处理        |
| Claude 3.5+ | 高       | 偶尔包裹代码块，需strip     |
| Gemini 2.0+ | 中       | 倾向在JSON前后加解释文字，需截取 |
| DeepSeek V3 | 中       | 偶尔输出不完整JSON，需重试    |
| Qwen 2.5+   | 中高      | 长JSON可能截断，建议分步执行   |

**通用JSON提取规则**：

1. 尝试直接 JSON.parse(fullOutput)
2. 失败则正则提取第一个 { 到最后一个 } 之间的内容
3. 仍失败则strip代码块标记后重试
4. 最终失败则重试该阶段（最多1次）

## 阶段0 附录：置信度 / 情感 / 可引用性定义（v1.0.0 新增）

### 置信度分档（confidence, 0-1）

| 档位 | 区间      | 判定标准                | 处置                                           |
| -- | ------- | ------------------- | -------------------------------------------- |
| 高  | ≥0.9    | ≥3个独立信源一致，且含官方/权威来源 | 可直接写入报告断言                                    |
| 中  | 0.7-0.9 | 2个信源一致，或单一权威来源      | 可写入，标注置信度                                    |
| 低  | <0.7    | 单一非权威来源/互相冲突        | **必须转入 opportunityMap.openQuestions**，不进正文断言 |

### 情感判定（sentiment）

| 取值       | 判定标准                              |
| -------- | --------------------------------- |
| positive | 明确褒扬/推荐                           |
| neutral  | 事实陈述/无倾向                          |
| negative | 明确贬损/投诉/风险揭露                      |
| mixed    | 同平台同时存在正负（取主导方向并在 topEvidence 体现） |
| null     | 该格未覆盖（covered=false）              |

保守原则：证据不足一律 neutral/null，不得为凑分布编造情感。

### 可引用性分档（citability）

| 档位     | 平台类型                   | 说明             |
| ------ | ---------------------- | -------------- |
| high   | 百科/权威媒体/头部社区（知乎/小红书热帖） | AI 高频引用信源      |
| medium | 普通媒体/公众号/垂直站           | 可能被引用          |
| low    | 职场点评聚合站/论坛散帖           | 极少被直接引用，可作舆情佐证 |

### 平台矩阵证据纪律（v2.1）

- 矩阵**不设 aiPrediction（AI 引用预判）列** —— 该列无 URL 支撑，属推断，v2.1 起整列删除。
- 矩阵每一格都必须能点回当次检索命中的原始页面（`topEvidence.url`）；命不中就 `covered=false`，不代以推理。
- 覆盖缺口排序只用可核验口径：某列 covered 平台数为 0 或极少 → 该列为该品类的高优先级机会。

### 实体消歧质量检查

- [ ] canonicalName 有 ≥3 信源或官方来源支撑
- [ ] 每个 sameNameEntities 都有 aiMisreadScenario 与 handling
- [ ] high 风险同名实体必须进 OPPORTUNITY_MAP（P0 消歧行动）
- [ ] 所有 URL 可追溯到当次搜索结果，无编造
