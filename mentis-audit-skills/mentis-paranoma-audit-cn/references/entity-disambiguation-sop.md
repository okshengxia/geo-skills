# 实体消歧 SOP（阶段0 模块1：ENTITY_MAP）

> 适用：mentis-paranoma-audit-cn 阶段0。字段契约见 `prompts.md` 阶段0 模块1。

## 一、入口纪律

- 入口只需**品牌名**；官网/产品类型可选，缺失不阻断（entityType 作为报告 category 兜底）。
- canonicalName 判定优先级：**官方来源（官网/官方公众号/官方百科）> 权威媒体 > 聚合站 > 搜索快照**。无官方来源时明确标注置信度上限 0.8。
- 一条铁律：**名字没弄清之前，后面全白干**。同名实体污染不处理，平台矩阵和可见性诊断都是给别人的品牌做嫁衣。

## 二、数据源清单（按优先级）

| 优先级 | 信源 | 用途 |
|--------|------|------|
| P0 | 品牌官网 / 官方公众号 / 官方百科词条 | 官方主名、法律主体、成立年份、总部 |
| P1 | 权威媒体（36氪/虎嗅/亿欧/界面/财新等） | 交叉验证、历史沿革 |
| P2 | 企查查/天眼查等聚合站 | 法律主体、分支机构（**仅公司维度**，不采个人信息） |
| P3 | 百科/搜索快照 | 别名与常见误写线索 |

## 三、名称矩阵规则（aliases）

- `lang`：zh-CN（简体主名）/ zh-TW（繁体）/ en（英文官方名）。
- `type`：官方别名 / 曾用名 / 简称 / **常见误写**。
- 常见误写必须单列并记录来源——实证：某热播职场剧把「亿康先达」误写为「亿康达」，这类误写是 AI 混淆的种子。
- 每个别名必须带 `url + date + confidence`；无来源的别名不进矩阵。

## 四、置信度分档

| 档位 | 区间 | 判定标准 | 处置 |
|------|------|----------|------|
| 高 | ≥0.9 | ≥3 个独立信源一致，且含官方/权威来源 | 可直接写入报告断言 |
| 中 | 0.7-0.9 | 2 个信源一致，或单一权威来源 | 可写入，标注置信度 |
| 低 | <0.7 | 单一非权威来源 / 互相冲突 | **必须转入 opportunityMap.openQuestions**，不进正文断言 |

## 五、同名实体判定树

```
发现同名/近音实体 →
├─ 同一法律主体或其子品牌？ ──是──→ relation=关联/子品牌，riskLevel 视业务重叠度
├─ 历史曾用名/前身？ ────────是──→ relation=曾用名，riskLevel=low（AI 混淆旧闻）
├─ 完全无关同名（不同行业/地域/业态）？
│   ├─ 搜索量/知名度高于本品牌 ──→ riskLevel=high
│   ├─ 知名度相当 ──────────────→ riskLevel=medium
│   └─ 知名度低 ───────────────→ riskLevel=low
└─ 简称撞名（本品牌简称 = 他品牌全称）？ ──→ relation=简称撞名，按上述知名度分级
```

- 每个 sameNameEntities **必填 `aiMisreadScenario`**：场景化写「当用户问 X 时，AI 可能引用 Y 的内容 / 把本品牌说成 Z」。禁写"可能混淆"这类空话。
- `handling` 落到动作：百科词条加消歧段 / 全渠道统一「品牌名（英文名）」 / 官方内容强化行业词共现。

## 六、行业包提示（按品类加载）

### 猎头 / 高管寻访业（亿康先达实证）
- **同名实体高发**：快消/生物科技/农业等同名公司；AI 回答「亿康先达是什么」时直接串味（早孕试纸、吉林农业等实证）。
- **收费口径第三方流传**（如「固定费约 10 万美元/单」）：无官方佐证前只记录不背书，进 openQuestions；官方不说 = 定价权交给传言。
- **合规敏感**：PIPL / 跨境人才数据 / 背景尽调——行业头部（Morgan McKinley、AESC）均发过原则声明，缺位即缺口。
- **决策人信息敏感**：候选人/客户高管姓名、职位变动属个人敏感信息，禁采禁录。

### 其他行业通用
- 消费品：警惕品牌名 = 通用品类词（如「鲜目录」类），同名不同类高发。
- ToB 软件：警惕被旧闻/停产产品线绑定，曾用名清理优先。
- 医疗/金融：监管表述敏感，负面词条风险权重上调一档。

## 七、隐私纪律（硬规则）

- **禁采**：个人主页 / 联系方式 / 简历 / 薪酬明细 / 候选人信息。
- 职场平台（脉脉/看准/职友集）只取**公司维度聚合**（公司评分、公司话题、面试体验条数），不摘录个人发言原文。
- 任何以个人为主体的页面，不进 `topEvidence`。

## 八、输出

→ `stage0.json` 的 `entityMap` 模块；confidence<0.7 的断言转 `opportunityMap.openQuestions`。
