# GEO诊断报告 - 搜索查询模板

> 各阶段执行搜索时的标准查询模板，使用 `{brandName}` 和 `{productType}` 占位。
> 搜索执行规范（速率控制、重试容错、结果验证）详见 `references/search-strategy.md`。
> **v4.0优化**：合并重复搜索，减少总搜索次数；明确并行分组。

---

## 阶段0 搜索组（站外全景审计，约11次→4组并行）

### 组A：实体消歧（3次并行）

```
搜索1: "{brandName}" 百科 品牌介绍
搜索2: "{brandName}" 公司 主体 成立 总部
搜索3: "{brandName}" 英文名 OR 曾用名 OR 别名
```

**结果提取**：官方主名、法律主体、成立年份、总部、中繁英别名矩阵。

### 组B：同名实体（2次并行）

```
搜索4: "{brandName}" 是什么
搜索5: "{brandName}" 招聘 评价 OR 新闻
```

**结果提取**：同名/近音实体清单（行业、地域、商业形态）、AI 误引风险素材。

### 组C：平台矩阵（3次并行）

```
搜索6: "{brandName}" site:zhihu.com OR site:xiaohongshu.com
搜索7: "{brandName}" 收费 价格 多少钱
搜索8: "{brandName}" 靠谱 投诉 合规
```

**结果提取**：各平台品牌词/评价/价格/信任/合规五类覆盖证据（标题+URL+日期）。

### 组D：信源缺口（2次并行）

```
搜索9: "{productType}" 推荐 排行 哪家好
搜索10: "{brandName}" 对比 哪个好
```

**结果提取**：品类推荐类信源结构、品牌在对比语境中的在场情况。

> 组A结果写 `<品牌目录>/search-cache/{brandName}-entity.json`，阶段1组A命中缓存则跳过。

---

## 阶段1 搜索组（5次→3次并行）

### 组A：品牌+竞品（3次并行）

```
搜索1: "{brandName} {productType}" 品牌 介绍 官网
搜索2: "{productType}" 品牌 排名 推荐 2025
搜索3: "{brandName} {productType}" 评测 体验 对比
```

**执行策略**：3次WebSearch同时发起，不设间隔。
**结果提取**：
- 搜索1 → 官网URL、品牌介绍、产品矩阵
- 搜索2 → 竞品名称、市场份额、排名
- 搜索3 → 自媒体/权威媒体评测URL和标题

> **v4.0优化**：将原6次自媒体site搜索+5次权威媒体site搜索+4次竞品搜索，合并为3次通用搜索。
> 原因：site搜索覆盖率低，通用搜索结果更全面，AI可从通用结果中提取各平台信息。

### 组B：补充搜索（2次并行，可选）

> 仅当组A结果不足时执行。

```
搜索4: "{brandName}" site:36kr.com OR site:huxiu.com
搜索5: "{brandName}" 负面 投诉 问题
```

**执行策略**：2次WebSearch同时发起。
**结果提取**：权威媒体URL、负面舆情关键词。

## 阶段2 搜索组（2次并行）

```
搜索1: "{brandName} {productType}" 推荐 AI搜索
搜索2: "{brandName} {productType}" 哪家好 对比 评测
```

**执行策略**：2次WebSearch同时发起。
**结果提取**：品牌在推荐类问题中的真实提及数据。

## 阶段3 搜索组（3次并行）

```

搜索2: "{brandName}" 口碑 评价 体验 怎么样
```

## 搜索缓存（v4.0新增）

执行搜索前，先检查 `diag-output/search-cache/{brand}-{product}-{type}.json` 是否存在且未过期：
- 实体缓存（entity）：30分钟
- 基建缓存（infra）：30分钟
- 竞品缓存（competitor）：1小时
- 舆情缓存（sentiment）：15分钟

缓存命中时跳过搜索，直接使用缓存结果。详见 `references/search-strategy.md`。
